# ADR 0008: Dantalion free plan and task-earned usage reset

- Date: 2026-10-03
- Status at recording: Accepted
- Source: Explicit user direction for Dantalion, a very limited free subscription, and task-completion usage resets; the user intentionally references the Ars Goetia demon.
- Supersedes: None; elaborates ADRs 0001 and 0007.

## Context

The current helper is a fixed local five-step hint ladder without an actual LLM/provider connection. The user wants a scarce free-plan allowance earned back through tasks.

## Decision

Brand the apparent LLM helper Dantalion. Give the player a very limited fictional free-plan allowance. Qualifying task completion resets the allowance; elapsed time alone is not the accepted reset mechanism.

Allowance numbers, response costs/units, eligible tasks, refunds/retries, repeat credit, per-scenario/account resets, and interactions with IT's wipe, difficulty, and Panopticon remain undecided. This decision requires no real LLM provider or network service. Track allowance behavior as G-13 alongside optional help under G-07.

## Why and alternatives

Scarce help makes deciding when to seek a hint part of play; task-earned resets can support independent practice. These are design hypotheses, not proven learning benefits. An unlimited helper or timer-only refresh would omit the requested limited-usage paradigm.

## Consequences

Preserve optional useful hints, no finished-code solutions, accurate technical documentation, and independently viable repair/refusal routes. Preserve the accepted helper-detection consequence while its scope remains open.

Fairness proposals remain unaccepted: qualifying tasks before hard gates and on both routes, capped replenishment without repeated-test farming, and quota refresh that leaves surveillance history intact. Specify these separately before treating them as rules.

## Verification

When implemented, check the selected allowance and qualifying task reset, distinguish quota from surveillance consequences, and verify the helper remains optional and puzzle-preserving. Confirm both routes remain independently viable and that elapsed time does not substitute for completing required tasks.

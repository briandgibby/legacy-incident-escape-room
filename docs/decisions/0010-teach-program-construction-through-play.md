# ADR 0010: Teach program construction through play

- Date: 2026-10-03
- Status at recording: Accepted
- Source: Explicit user request that the game teach how to construct a computer program, beyond the existing debugging focus.
- Supersedes: None; elaborates the educational purpose in ADR 0001.

## Context

The current scaffold asks players to investigate and repair incidents. Puzzle completion alone does not demonstrate understanding of program construction.

## Decision

Make program construction an explicit goal beyond debugging and syntax recall. Teach through real-code play and explanations of choices. Do not claim a universal best architecture or treat the current incident as proof of success.

Curriculum, intended audience, concrete scenario content, and teaching sequence remain unresolved. No particular construction workflow or additional scenario pack is accepted by this record. Track this capability as G-14.

## Why and alternatives

Debugging alone may not teach players how to begin their own program. Explicit construction goals address that gap. Choosing an architecture before audience and exercises would turn an educational aim into an unsupported implementation rule.

## Consequences

Preserve real-code authenticity, minimal architecture, optional credit-limited Dantalion help, and manual reasoning. Refusal remains viable without compulsory code repair. This goal authorizes neither new frameworks nor implementation of unchosen content.

## Verification

Evaluate selected teaching content through an observed transfer exercise in which players apply learning to a changed or new task. This provides stronger evidence than puzzle completion alone. Record observations; effectiveness remains a hypothesis until tested, and one exercise cannot establish universal teaching success.

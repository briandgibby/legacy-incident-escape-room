# ADR 0011: Initial audience and deferred beginner lessons

- Date: 2026-10-03
- Status at recording: Accepted
- Source: Explicit user selection of learners who already write basic code but need help organizing programs; beginner lessons deferred until the core game has a functional skeleton.
- Supersedes: None; narrows the initial audience in ADR 0010.

## Context

ADR 0010 establishes teaching program construction as a product goal while leaving audience and curriculum open. The user has selected a starting audience and sequencing boundary.

## Decision

Initially serve learners who can already write basic code and need help organizing programs. Defer absolute-beginner lessons until the core game's functional skeleton baseline exists.

Exact curriculum, assumed basic-code fluency, and the definition and acceptance criteria of that baseline remain unresolved. This decision does not approve a teaching sequence, new scenario pack, or universal best architecture.

## Why and alternatives

This audience lets the initial teaching focus on construction and organization without simultaneously introducing every programming fundamental. Starting both curricula now would broaden the initial scope before the core game works.

## Consequences

Keep real-code authenticity, minimal architecture, and explicit learning hypotheses. Future beginner support remains a direction rather than current implementation work. Preserve optional help and independently viable repair/refusal routes; construction lessons must not silently make incident repair mandatory.

## Verification

Review proposed first exercises for audience fit and document their assumed fluency. Define and verify the core baseline before introducing the deferred beginner lessons. Use observed transfer to assess learning, without treating puzzle completion as proof of program-construction understanding.
